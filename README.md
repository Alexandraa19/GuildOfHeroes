## Собственный проект

Тема проекта: Коллекция фильмов

Главный класс: Movies

Почему этот объект нужен программе:
Программа хранит и отображает информацию о фильмах

Какие данные хранит объект:
- Name - название фильма
- Year - год выхода
- Genre - жанр
- Rating - рейтинг


Какие значения задаются через конструктор:
Name,Genre Year, Rating - эти данные уникальны для каждого фильма и передаются при создании.

Какие значения можно задавать автоматически:
При создании объекта через конструктор передается рейтинг. Программа сохраняет его в поле. 
В дополнительном задании это значение можно изменить позже, не передавая его повторно в конструктор
### Дополнительное задание

Какое значение я решила задавать автоматически и почему?
В качестве дополнительного задания я показала изменение состояния объекта после его создания.
При создании фильма "Крик" я передала начальный рейтинг 6.6:
`Movies scream = new Movies("Крик", "Ужасы", 1996, 6.6);`

Затем, без создания нового объекта и без вызова конструктора, я изменила это значение прямо в программе:
`scream.Rating = 7.2;`
Это сразу показывает, что объект хранит собственное состояние, и его можно изменять автоматически  в ходе работы программы

### Поведение главного класса
пять методов экземпляра класса:
- TakeDamage(int damage) - наносит урон, отклоняет damage <= 0, не опускает здоровье ниже 0;
- Heal(int amount) - восстанавливает здоровье, отклоняет amount <= 0;
- GainExperience(int amount) - накапливает опыт, отклоняет amount <= 0;
- IsAlive() -возвращает bool: Health > 0;
- GetInfo() - возвращает строку с информацией о герое, ничего не печатает.

Проверка недопустимого урона: yaroslav.TakeDamage(-20) не изменил здоровье (осталось 75).
Сильный урон: artem.TakeDamage(200) остановил здоровье Артёма на 0.
Итоговые значения:
- Ярослав: Health = 85, Experience = 65;
- Анастасия: Health = 60, Experience = 0;
- Артём: Health = 0, Experience = 0.

  1. Действие выполняет объект слева от точки - `yaroslav`. Метод объявлен один раз в классе,
   но `Health` внутри метода — поле получателя вызова. Артёму метод не вызывали, его `Health`
   не меняется. Аргумент `25` попадает в параметр `damage`.

2. `return;` в `TakeDamage` -ранний выход из `void`-метода, ничего не возвращает и
   предотвращает недопустимое изменение. `return Health > 0;` в `IsAlive` -возвращает
   значение типа `bool` в место вызова (`true`/`false`) и завершает метод.

3. `string info = yaroslav.GetInfo();` - получаем строку в переменную, не печатая.
   Позже её выводит `Console.WriteLine(info);`.

   ###  класс Movies
Метод 1: `ChangeRating(double newRating)`
Что делает: изменяет поле `Rating` — устанавливает новый рейтинг фильма.
Перед изменением проверяет допустимость: если `newRating < 0` или `newRating > 10`,
метод завершается через ранний `return;`, и рейтинг остаётся прежним.
Тип возврата — `void`.
Метод 2: `IsModern()`
Что возвращает: `bool` - `true`, если фильм выпущен в 2000 году или позже,
иначе `false`. Значение вычисляется по текущему состоянию поля `Year`:
`return Year >= 2000;`. Состояние объекта не изменяет

Почему эти действия относятся именно к этому классу:
Рейтинг фильма по смыслу ограничен диапазоном 0…10 -это свойство фильма,
поэтому проверку диапазона логично держать внутри `Movies`, чтобы каждый объект
пользовался ею одинаково. Признак «современный фильм» вычисляется из года выпуска -
это вопрос, на который отвечает сам фильм, а не внешний код. Поэтому `Program.cs`
только поручает действия объекту и печатает результат, а правила остаются в классе
`Movies`
